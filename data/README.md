# Data files

All four files are synthetic, generated by [`generate_data.py`](generate_data.py) with a fixed
seed (`20260727`), so regenerating gives byte-identical output.

They are deliberately imperfect. Real instrument data carries drift, dropouts, sentinel
values and formatting quirks, and learning to handle those is half of what notebook 04 is
about.

---

## `ecg_like.csv`

Single-channel ECG-like biosignal.

| | |
|---|---|
| Columns | `time_s`, `mV` |
| Rows | 7200 |
| Sampling rate | 360 Hz |
| Duration | 20 s |

**Signal content.** A P-QRS-T beat complex at roughly 72 bpm, with the rate modulated ±4 bpm
at 0.25 Hz (respiratory sinus arrhythmia — genuine physiology, and the reason the heart-rate
trace in notebook 03 is a sinusoid rather than a flat line).

**Deliberate defects.**

| Defect | Where it shows up |
|---|---|
| Baseline wander, 0.22 Hz and 0.05 Hz | Removed with a 0.5 Hz high-pass |
| 50 Hz mains hum, 0.08 mV | Removed with `signal.iirnotch` |
| Gaussian noise, σ = 0.03 mV | Reduced with a 40 Hz low-pass |

Used in: notebook 01 §13, notebook 03 §16 (the full cleaning case study), notebook 04 §2.

## `accelerometer.csv`

Three-axis accelerometer with real timestamps.

| | |
|---|---|
| Columns | `timestamp`, `acc_x`, `acc_y`, `acc_z` |
| Rows | 11800 |
| Sampling rate | 100 Hz nominal |
| Duration | 120 s, starting `2026-03-14 09:15:00` |

**Signal content.** A 1.9 Hz walking cadence with its 3.8 Hz harmonic, gravity (~9.81 m/s²) on
the z-axis, and a low-amplitude 11 Hz tremor. A **3-second vibration burst at 24 Hz** runs from
t = 61 s to t = 64 s — this is the event the notebooks detect.

**Deliberate defects.**

| Defect | Detail |
|---|---|
| Random dropouts | ~1.5% of samples per channel are `NaN`, independently per channel |
| Logger stall | Rows for t = 88–90 s are **absent entirely** — the timestamps jump |

That second one is the important one: the gap is invisible in a row count and only shows up if
you check `index.to_series().diff()`. Feeding the array to an FFT as though it were contiguous
gives wrong answers with no warning.

Used in: notebook 02 exercises, notebook 03 exercises, notebook 04 §6–§9, notebook 05 §7 and §9.

## `bench_capture.txt`

A fictional DAQ-2200 bench capture, written in the most inconvenient plausible format.

| | |
|---|---|
| Columns | `index`, `time_s`, `channel_a_volts`, `probe_temp_c`, `status` |
| Samples | 4000 |
| Sampling rate | 500 Hz |

**Signal content.** 7 Hz and 43 Hz components plus Gaussian noise, and a probe temperature
drifting slowly upward.

**Deliberate defects.**

| Defect | Why it matters |
|---|---|
| 8 comment lines then a blank line | `skiprows=8` is fragile; `comment="#"` is not |
| `;` delimiter **with spaces on both sides** | `sep=";"` alone leaves trailing spaces, so sentinels stop matching and the column silently becomes `object` |
| `# --- keepalive ---` banners every 1500 rows | mid-file comments that `skiprows` cannot handle |
| No header row | column names live in a comment |
| Two sentinels: `NaN` and `-999.0` | both mean "no reading"; the second will poison a mean if undeclared |
| `status` column (`OK` / `SAT` / `ERR`) | the authoritative validity flag |

The correct read is `sep=r"\s*;\s*", engine="python", comment="#", na_values=[...]` — worked
through step by step in notebook 04 §3.

Used in: notebook 01 exercise 7, notebook 04 §3–§5, notebook 05 exercise 1.

## `filter_sweep.csv`

Benchmark results for a filter design sweep, in tidy long format.

| | |
|---|---|
| Rows | 750 = 5 families × 5 orders × 5 cutoffs × 6 trials |
| Keys | `family`, `order`, `cutoff_hz`, `trial` |
| Metrics | `rolloff_db_per_octave`, `passband_ripple_db`, `group_delay_ms`, `output_snr_db` |

Families: `butter`, `cheby1`, `cheby2`, `ellip`, `bessel`. Orders 2–10, cutoffs 20–100 Hz.

**These numbers are modelled, not measured** — generated from the qualitative behaviour of each
family (elliptic rolls off steepest and ripples most, Bessel is gentlest with near-zero ripple,
group delay grows with order and falls with cutoff) plus trial-to-trial noise. They are
realistic enough to practise `groupby`, faceting and comparison on, but do not cite them as
measurements.

**Exercise 4 of notebook 04 asks you to regenerate this file for real** — actually design each
filter, actually measure each metric — and compare against these synthetic values.

Used in: notebook 04 §10–§12, notebook 05 §5–§8.
